# Marrow notes

What every marrow agent should know about this repo. `/marrow setup` writes it and `/marrow retro` adds lessons; edit it freely. Agents read all of it on every run, so keep it short.

## Builds

`cloud`. Origin is GitHub (`sunnyeyles/lintcat`), the Claude GitHub app is installed, and no check needs a local service.

## Checks

`.marrow/checks` mirrors `.github/workflows/ci.yml`: pnpm install (frozen lockfile), typecheck, lint, knip dead-code, `pnpm test`, the cli/mcp/worker esbuild bundles, and `scripts/smoke-cli-mcp.mjs`. Nothing beyond Node 22–25 and pnpm 10: no database, no env vars, no running server. The Next.js `web` build and `pnpm eval` are not checks (CI skips the first; the second spends real model tokens).

## Tests

Vitest, `*.test.ts` beside their sources, every workspace a project in the root `vitest.config.ts`. One file: `pnpm vitest run packages/reviewer/src/validate-findings.test.ts`, add `-t "<name>"` to narrow. `*.conformance.test.ts` hold a fake to the same contract as the real implementation. DB tests use in-process PGlite (`@electric-sql/pglite`). Eval fixture repos live in `evals/fixtures/`. Tests never call a model.

## Parallel tickets

Safe: each test opens its own in-memory PGlite, nothing listens on a port, temp dirs come from `mkdtemp`. Lanes: 3.

## Conventions

Root `AGENTS.md` (trust boundary: model output never reaches GitHub unvalidated; `#src/` imports, no `.js` suffixes; semantic colour tokens only, enforced by `packages/design/src/tokens-guard.test.ts`; comments at most 2 lines), the nested `AGENTS.md` in `apps/web`, `packages/ai`, `packages/db`, `packages/design`, `evals`. The repo keeps no ADRs; never create `docs/adr/`.

Not written down elsewhere:

- `packages/db/drizzle/*.sql` and its meta are generated by `pnpm db:generate`; never hand-edit them.
- `apps/web` changes follow Vercel's React best practices (the `vercel-react-best-practices` skill).
- Never run `pnpm eval`: it spends real tokens.
