# Storyboard: how a LintCat review runs, in eight drawings

One idea per stage. Each drawing assembles itself mark by mark in the order a viewer needs it,
then holds on the finished picture. The pictures are for people; this table is the same content
for agents, with the code each stage cites. Read it top to bottom to trace a review, or jump to
stage 5 to see how blast radius is traced.

Kind: explainer. Style: anidoodle `pixelArt` in the LintCat brand palette (the mark is pixel
art, so the guide character is the mark itself). Shape 16:9, 192 x 108 cells. Silent.
30 fps at 120 bpm, cels held 3 frames, a 1.5 s hold at the end of each stage.

## What is simplified

- Stage 5's graph is a sketch of a real shape (worker, CLI and MCP all import `review-run.ts`),
  with short labels; the numbers on the dial are illustrative, not measured.
- Stage 6 shortens `list_changed_files` to `CHANGED_FILES` to fit the drawer; the exact tool
  names are in the Cites column.
- The MCP and CLI entry points run the same pipeline without the webhook, queue or worker
  (stages 1–3): see `apps/mcp/src/local-review.ts` and `apps/cli/src/review-command.ts`.
